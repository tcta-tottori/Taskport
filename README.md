# Taskport

タスクとスケジュールを、どの端末からでも・どんな方法でも入れられて、必要な形で出せるようにするための個人用ハブ。

**port = 入出力ポート。** 多数の入口と出口が、一つの台帳につながっている。

---

## 入口（Ports In）

| 経路 | 使う場面 |
|---|---|
| 音声 | 現場を歩いている時、会議直後。喋るだけで複数タスクに分解される。画面を消しても録音は続く |
| キーボード（自然文） | PCの前。メールの文面をそのまま貼ってタスク化 |
| フォーム直接 | 件名と期限だけ分かっている時の最短経路 |
| 他アプリから共有 | Gmail・LINE の共有メニューから直接投げ込む |
| 予定 | 打合せ・来客・固定の業務。＋の扇（真上）から入れる |

自然文はすべて同じパイプラインを通り、タスク候補に分解される。
解析は**端末内で完結**し、外部のAIサービスには送らない。
**候補は必ず確認画面に出る。無確認では登録されない。**

## 出口（Ports Out）

- 一覧ビュー（検索・絞り込み＋今日 / 今週 / すべて / 完了）
- スケジュールビュー（勤務時間のタイムライン＋2週間の日付軸）
- 分析ビュー（処理の推移・区分ごとの時間と構成比・優先度分布・入口別）
- Googleカレンダーへ書き出し（登録URL / .ics）／連携して直接追加
- 業務日報（エクセルに貼り付けられる30分刻みの表）
- 日報・朝会用テキスト
- CSV

## スマホとPCで共有する

同じ台帳をどちらの端末からも使える。**既定は切**で、設定画面から入れる。

- 置き場は**自分の Google Drive のアプリ専用フォルダ**。マイドライブには出てこず、
  ほかのアプリからも Drive の画面からも見えない
- **入れると、タスクの件名・メモ・区分が Google に保存される**（それまでは端末の中だけ）。
  音声は今までどおり外へ出さない
- Googleカレンダーと同じクライアントIDを使う。追加で要るのは権限（スコープ）1つだけ
- 合わせるのは、アプリを開いたとき・画面に戻ったとき・変更してから数秒後
- 突き合わせは**1件ずつ更新時刻の新しいほう**。削除は跡（墓標）で伝えるので、
  消したタスクが相手から戻ってこない
- **同じ1件を2台でほぼ同時に直すと、あとから保存したほうだけが残る**
- やめるときは設定から切る。Google に置いたぶんは「置き場を空にする」で消せる
  （両方の端末で切ってから消す）

同期するのはタスクだけ。勤務時間や保存した絞り込みは端末ごとに持つ。

## 会社カレンダー

祝日・一斉有給・年末年始・土曜出勤など、**曜日だけでは決まらない日**を実日付で持つ。
稼働率・空き時間・スケジュール・「稼働日ごと」の繰り返しが、これに従う。

入れ方は4つ。どれで入れても、あとから月の枠で直せる。

- **配られたカレンダーを入れる** — 2026年7〜12月ぶんを写し取ってある。ボタン1つで入る
- **写真から読み取る** — 紙のカレンダーを撮って、**その月の日付が並ぶ範囲**を四角で囲むと、
  **赤い日を休みとして拾う**。数字は読まず色だけを見る（何日がどのマスかは年と月から計算で分かる）。
  写真も判定も端末の中だけで、外へは何も送らない。読んだ結果は押して直してから取り込む
- **Googleカレンダーから取り込む** — 会社のカレンダーを Googleカレンダーに追加してあるなら、
  そのIDを入れて終日予定を読む。件名から休み／出勤を見当づける（祝日の名前も拾う）。
  当てられないものは選んでもらう
- **月の枠を押して入れる** — 紙で配られたカレンダーを見ながら、1日ずつ押していく。
  押すたび 曜日どおり → 休み → 出勤 と回る

年間の稼働日数・休日数と、**月ごとの内訳**が出る。紙の数字と1行ずつ見比べて、
入れ間違いを自分で確かめられるようにしてある。

会社カレンダーは端末どうしで同期する（設定の中でこれだけ）。

> 写し取ってある2026年7〜12月は、紙のカレンダーを人が読んだもの。
> 平日の休みがすべて祝日か紙の一斉有給と一致すること、7〜12月の稼働122日・休62日が
> 紙の「年間稼働251日・年間休日114日」と矛盾しないことは確かめてあるが、
> **使う前に月ごとの内訳を紙と突き合わせてほしい**。1〜6月は紙が無いので入っていない。

## 今日の進めかた

一覧の上（今日タブ）に、その日を回すための面がある。

- **いま やる1件** — いまの時間枠の先頭を1件だけ大きく出す。終わると次に入れ替わる
- **時間枠ごとの積み上げ** — 枠の長さと見積もりの合計を並べる。
  枠は勤務時間の区切りそのもの（8:20〜10:20 など＝日報の時間区分）。
  あふれていれば朝の時点で分かる
- **朝の仕分け** — 期限切れを1件ずつ出し、今日やる（枠も選ぶ）／明日へ／期限を外す／
  もう終わっている の4つから選ぶ
- **明日の準備** — 終わりに、今日のやり残しと明日ぶんを並べる。その場で明日へ送れる

## 予定（打合せ・固定の業務）

タスクとは別に**予定**を入れられる。タスクが「やること」なら、予定は「その時間そこにいること」。
完了の丸は付かず、時間だけが埋まる。

- **右下の ＋ の扇（真上・色違いの1つ）**、カレンダー（月表示）、スケジュールの
  「予定を入れる」から作る。扇から入れたときは今日が下敷きになる
- 件名・日付・開始と終了・終日・場所・区分・繰り返し・メモ
- 繰り返しは**作り置きしない**。1件持つだけで、毎回ぶんがカレンダーとスケジュールに出る。
  やめるときはその1件を消せば先の回も消える
- Googleカレンダーから読む予定とは別物（あちらは読むだけ。こちらは端末の中で作って直せる）

## カレンダー（月表示）

1か月を一面で見て、山と空きを掴む画面。予定とタスクを**同じ升目**に並べる
（別々に見ると、会議で潰れている日にタスクを積んでしまう）。

| 端末 | 升目の中身 |
|---|---|
| 狭い（〜720px） | 予定＝四角・タスク＝優先度の色の丸。あふれたぶんは「+n」 |
| 広い（720px〜） | 件名の入った帯。あふれたぶんは「ほか n件」 |

升目の下の細い棒は、タスクの見込み時間が勤務時間のどれだけを埋めているか。
日を押すと下にその日が開き、そこから予定・タスクを足したり、実行を始めたりできる。
会社カレンダーの休みは地の色を落としてある。

## 実行（いま動かす・その日の記録）

「いま何に手を付けているか」と「その日に何をやったか」を1つの画面で扱う。
見込み時間ではなく**実績**を数える面。

- **いま動いているもの** — タスクと予定が並ぶ。止める／再開／終了。
  **同時に何本でも**動かせる（電話を受けながら伝票を打つ、が実際に起きる）。
  2本以上動いていると、合計が実時間を超えることを画面に書く
- **次にやる** — 今日締め（超過ぶんを含む）を上から。先頭に「次」の印。▶ でその場から始まる
- **その日の予定** — いまの時間の予定を立てて出す。自動／手動はここで切り替えられる
- **近日の締め** — 明日から1週間。前倒しできるものを拾う
- **その日の記録** — 開始時刻とかかった時間をその場で直せる。日報はここから書き出す
- **やったことを足す／区分から始める** — 台帳に無い仕事を1件立てる。
  区分から立てたものはその場で動き出す（＋は立てるだけ）

実績の置き場は2つに分かれている。**混ぜないための分担**で、どちらも1か所にだけ記録される。

| 何の実績か | どこが持つか | 直せるか |
|---|---|---|
| タスク | 台帳（`startedAt` / `actualMin`） | 記録の画面から直せる。同期・書き出しにも乗る |
| 予定 | 予定の実行ログ（端末内のみ） | 区間の記録なので直さない。消すときは記録ごと |

予定を**自動**にしておくと、開始時刻で始まり終了時刻で終わる。
アプリを閉じている間に過ぎたぶんは、その日ぶんだけ後から埋める。
手で止めた記録・終えた記録には触らない（人の操作が常に優先）。
予定の記録は同期にも書き出しにも乗せない（90日より古いぶんは捨てる）。
ただし**日報には出す** — 出た会議が載らないと、その時間だけ空欄になるため。

実行を終えてもタスクは完了にならない。完了にするのは丸を押したときだけ。

## 見つける

台帳が増えてもタブだけで探さずに済むよう、一覧の上に検索と絞り込みを置いている。

- 件名・メモ・区分・手順を横断。空白区切りは AND。「ＡＢ－１２３４」でも「ab-1234」に当たる
- 区分（大分類）／優先度／期限（超過・今日・7日以内・それ以降・期限なし）で絞る
- 絞り込み中はタブを離れ、全件から探す
- よく使う条件は名前を付けて残せる

## 繰り返しと手順

- **繰り返し** — 毎日／稼働日ごと／毎週（曜日）／毎月おなじ日／毎月末。
  完了にすると次の1件だけができる。「毎週月曜に…」のように喋っても拾う
- **手順（サブタスク）** — 1つの作業を工程に分けて、カードから直接潰せる。
  繰り返しの次回にはチェックを外して引き継ぐ

## リマインド

**時刻を入れたタスク**の N 分前（既定10分）に通知する。設定から入れる（初期値は切）。

| 端末 | 動き |
|---|---|
| 予約つき通知に対応（Chrome 系） | 7日先までを預ける。**アプリを閉じていても出る** |
| 非対応 | **アプリを開いている間だけ**出る |

いまどちらで動いているかは設定画面に出る。
通知は端末内だけで組み立てる。プッシュサーバを持たないので、予定が外へ出る経路はない。

## 録音

録音まわりは同じ作者の [NoteLoop](https://github.com/tcta-tottori/NoteLoop) 9.2 と同じ仕組み。
違うのは出口だけで、議事録ではなくタスク候補を作る。

- **見た目は NoteLoop 9.2 と同じ**（経過時間・縦バーのゲージ・3つのボタン）。
  ただし全画面ではなく**画面下半分のポップアップ**で出るので、一覧を見ながら喋れる
- **画面を消しても録音は続く。** 常駐通知に経過時間とゲージが出て、そこから一時停止・録音完了ができる
- **ゲージはマイクの実際の音量で動く。** 音声認識が返ってこない場面でも、喋れば伸びる
- **取りこぼし対策。** 3秒ごとにデータを確保し、止まっていたら録り直して継ぎ足す。
  経過時間より音声が短ければ停止時に知らせる
- **音声は端末内にだけ残る。** 新しい方から20本まで。録音履歴から再生・保存・削除ができる。
  設定で保存を切ることもできる

外部に出るのは認識後のテキストだけで、音声そのものは送信しない。

## 勤務時間

スケジュールと稼働率の計算に使う。設定画面から変更できる。

| 項目 | 既定値 |
|---|---|
| 始業 | **8:20** |
| 小休憩 | **10:20 〜 10:25** / **15:05 〜 15:10** |
| 昼休憩 | **12:25 〜 13:05** |
| 終業 | **17:10** |
| 実働 | **8時間ちょうど**（480分） |

小休憩は設定画面で増減できる。実働は始業から終業までの時間から、
昼休憩と小休憩をすべて引いた値。

「今日のタスクを全部やったら勤務時間に収まるか」を、一覧の上と分析画面のゲージで出す。
見込み時間を入れていないタスクは、設定の既定値（初期値30分）で積む。

## 業務分類

区分は、実際に使っている資材課日報の作業内容をそのまま候補にしている
（8つの大分類・35の小分類）。自然文から推測できたものは確認画面に既に入った状態で出る。
候補にない区分を自由に書いてもよく、その場合は「その他」として集計される。

## 端末ごとの作り分け

| | スマホ | PC |
|---|---|---|
| ナビ | ハンバーガーで開く | 左に出しっぱなし |
| 一覧 | 1カラム。検索とタブはヘッダー下に貼り付く | 左＝その日の状況／右＝探して片づける の2カラム |
| 分析 | 1カラム | カードを2〜3枚ずつ横に |
| 入力 | 下のドック（親指の届く位置） | 文字入力欄を開いたまま |
| 操作 | タップ（最小 44×44px） | `/` 探す・`n` 直接入力・`e` 書き出し・`1〜4` タブ・`Esc` 閉じる |

見分けは幅だけでなく「細かく指せる装置があるか」も見る（タブレットは広くても指で触るため）。

## 動作環境

- **Android Chrome**（主）
- **PC Chrome**（副）
- PWA。ホーム画面に追加してオフラインでも動く
- 音声入力は Chrome 前提。非対応環境では自動的にキーボード入力に切り替わる

## データの扱い

- 音声は端末内で文字に変換され、**音声データそのものは外部に送信されない**
- 録音した音声も端末内（IndexedDB）にのみ保存。外部へは出ない
- 自然文の解析は端末内で完結。外部のAIサービスには送らない
- カレンダーの写真も端末内でだけ読む。画像も判定結果も外へは送らない（文字認識にも出さない）
- タスクと予定は端末内（IndexedDB）に保存。設定画面から JSON で書き出し・取り込みができる
- 予定の実行の記録（開始・終了）は端末内だけ。同期にも書き出しにも乗せない
  （別の端末へ移すと同じ時間が二重に立つため）。タスクの実績は台帳に入るので、
  書き出しにも同期にも乗る
- **例外はGoogleカレンダーへの追加だけ。** 押したときに選んだタスクの件名とメモが Google に渡る
- Googleのトークンはメモリにのみ置き、localStorage には保存しない

## 開発

```bash
npm install
npm run dev        # 開発サーバ
npm run build      # 本番ビルド（dist/）
npm run preview    # ビルド結果の確認
npm run lint       # 型チェックのみ
```

`main` に push すると GitHub Actions が `gh-pages` ブランチへ配信する。
Pages の Source は「Deploy from a branch → gh-pages / (root)」に設定しておく。

公開URL: **https://tcta-tottori.github.io/Taskport/**

`vite.config.ts` の `base` はリポジトリ名（`Taskport`）と完全に一致させること。
リポジトリ名を変えたら `base` も合わせる。ずれると全アセットが 404 になる。

### Googleカレンダー連携（任意）

設定画面に Google Cloud の各ページへ飛べるリンクと、承認済み生成元のコピーボタンがある。
手順は「Calendar API を有効化 → OAuth 同意画面 → クライアントID を作る → IDを貼る」の4つ。


**未設定でもアプリは動く。** 使う場合は、自分の Google Cloud で用意する。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る
2. **Google Calendar API** を有効にする
3. OAuth 同意画面を作る（外部／テストユーザーに自分を追加）
4. 認証情報 → OAuth クライアントID → **ウェブアプリケーション**
5. 「承認済みの JavaScript 生成元」に配信元を入れる
   （公開版なら `https://tcta-tottori.github.io`、手元なら `http://localhost:5173`）
6. 出てきたクライアントIDを、アプリの「設定 → Googleカレンダー」に入れて「Googleと接続」

できること:

| 向き | 内容 |
|---|---|
| 読込 | 2週間分の予定をスケジュールに重ねて表示。台帳には混ぜない |
| 取込 | 予定をタップするとタスク候補になる。確認画面を通してから登録 |
| 追加 | 書き出し画面で選んだタスクを予定として追加 |

**予定を追加すると、そのタスクの件名とメモが Google に渡ります。**
自動では送りません。押したときに選んだ分だけです。
